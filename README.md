# 中国移动资费公示专区 · 抓取器（浏览器版）

抓取**指定省份**「资费公示专区」的全部业务，按**上线日期从最新到最晚**倒序排列。
新上线的业务自动识别并置顶高亮 —— 打开报告一眼就能看到动没动过。

数据源：`https://h.app.coc.10086.cn/cmcc-app/pc-pages/tariffZonePers.html`

支持 **Windows（PowerShell / cmd）** 与 **Debian / Ubuntu**。

> **两个版本，按需选**
>
> | | 本仓库（浏览器版） | [cmcc-tariff-api](https://github.com/cherry10086/cmcc-tariff-api)（纯 API 版） |
> |---|---|---|
> | 单省耗时 | 12 分钟上下 | **28 秒** |
> | 依赖 | puppeteer-core + 本机浏览器 | **零依赖** |
> | 站点改版后 | **大概率仍可用** | 直接失效 |
> | 原理 | 驱动浏览器，让页面自己加解密 | 逆向加密网关直接调接口 |
>
> 想要**长期稳定**用这个；想要**快**、且能接受「站点一改就失效」用 API 版。
> 两个版本会互相印证 —— 数字对不上就说明有一边出问题了，这是发现静默 bug 最有效的手段。

> **不做全国批量。** 一次抓取 = 一个省的「个人/政企 × 全网/本省 × 四种资费类型」。
> 31 省连拉会被源站当成恶意爬虫，也容易把自己的 IP 拖下水。

## 安装

需要 Node.js 16+ 和本机浏览器（Chrome 或 Edge）。脚本驱动本机浏览器访问页面，不下载额外的 Chromium。

```bash
cd cmcc-tariff
npm install
```

**Debian / Ubuntu** 若没有浏览器：

```bash
sudo apt update && sudo apt install -y chromium fonts-noto-cjk
```

**Windows** 装 Chrome 或 Edge 即可。装在非默认路径时用环境变量指定：

```powershell
$env:CHROME_PATH = "D:\path\to\chrome.exe"   # PowerShell
set CHROME_PATH=D:\path\to\chrome.exe        # cmd
```

## 快速开始

```bash
node tariff-scrape.js --list-provinces     # 1. 查省份名
node tariff-scrape.js -p 北京市             # 2. 抓北京，自动打开报告
```

跑完自动打开 `data/北京市-report.html`。

一次抓多个省（会逐个串行，别贪多）：

```bash
node tariff-scrape.js -p 江苏省 -p 上海市
```

**耗时**：北京（16 个组合）实测约 12 分钟。只想看某类数据可以用 `--type` / `--scope` 缩小范围，比如 `--scope 全网 --type 套餐` 只跑 2 个组合，一分多钟就出结果。

## 输出物

| 文件 | 说明 |
|---|---|
| `data/<省>-report.html` | ⚡ **可视化报告**，倒序排列，新增业务绿框置顶。单文件零依赖，双击即开 |

| `data/全国总览.html` | 多省汇总（抓过 2 个以上省才有内容），也可用 `--overview` 单独生成 |

### 报告内筛选

搜索框按输入内容自动分两种走法：

| 输入 | 行为 |
|---|---|
| `0元`、`15.9元`、`0元/月` 这类价格词 | **价格精确匹配** —— 只留资费标准数值相等的条目 |
| 其它任意文字 | 业务名 / 方案编号 / 资费标准的子串匹配（原有行为，不受影响） |

**为什么要给价格词单开一条路**：子串匹配下搜「0元」会把 10元、100元、1000元 全捞出来。而 0 元资费恰恰是各省级清单里最该看准的一档 —— 实测上海 318 条、江苏 369 条、北京 225 条，被几百条含 0 的其它价格淹没就失去意义了。

搜索框下方另有 **「排除校园相关」** 勾选框，可与搜索叠加。判定只看两处：

- **业务名称**命中 校园 / 高校 / 学校 / 学生 / 学籍 / 新生；
- 或**适用范围**里正向描述的目标客户命中（如「校园用户」「电子学生证客户」）。

不扫其它字段，是因为误伤率高：资源表写着「1000M（河北校园300M)」的其实是普通宽带套餐；适用范围里的「政企/校园/功能等宽带**不适用**此活动」是排除条款，说的是这个业务**不**面向校园。后者现已按句切分、跳过带否定语气的句子。口径收敛后实测：广东家庭宽带提速包等 **18 条通用业务不再被误排除**，同时**多认出 80 条**真正面向校园客户的业务。

要调整口径改 `tariff-scrape.js` 顶部的 `CAMPUS_RE`。

被整个过滤掉的区块会连标题一起收起，不会出现「标题写着 N 条、下面一片空白」。

> 这两项筛选只在单省报告里，全国总览是跨省索引页，不带它们。

**验证这一节的行为**（改过渲染代码后请跑一遍）：

```bash
node verify-report-filter.js                    # 默认用上海数据
node verify-report-filter.js --province 江苏省
```

它拿真实数据渲染报告，再驱动浏览器模拟搜索与勾选，把「页面上实测的可见卡片数」与「Node 侧按同一口径算出的预期值」逐项对账 —— 两边各算各的，对不上就是有 bug。之所以需要它：报告里的筛选是页面内 JS，写在模板字符串里，光读源码看不出有没有被改坏（踩过一次 —— 正则写进模板字符串后 `\d` 被吃成 `d`，筛选静默失效）。

## 抓取范围

三个维度全组合，默认全抓：

```
个人资费 / 政企资费  ×  全网资费 / 本省资费  ×  套餐 / 加装包 / 营销活动 / 港澳台国际资费
```

**为什么要遍历资费类型**：页面默认只显示「套餐」，另外三类完全不出现（详见下文「资费类型」一节）。不去要，就会漏掉 98% 的数据。

同一方案编号若在多个组合中出现，会合并为一条，标签保留全部归属。

---

## 排序规则

主排序键是**上线日期**，降序 —— 最新的在最上面。

两处例外，都是为了让「刚上线的业务」永远留在第一屏：

- **预约上线沉底**。源站存在生效日期在未来的预约业务（实测北京有 16 条），按纯日期倒序它们会霸占顶部，把真正的新业务挤下去。报告里归入独立的「预约上线」区块，终端用 `*` 标注。
- **无日期记录置底**。解析不出日期的不给假日期，直接沉底。

同日多条按名称做稳定排序，保证多次运行顺序一致。

## 资费类型：页面默认藏了 98% 的数据

页面上有个「资费类型」下拉，**默认停在「套餐」**，另外三类完全不显示。北京「个人资费 · 全网资费」实测：

| 资费类型 | 条数 |
|---|---|
| 套餐 | 43 |
| **加装包** | **1551** |
| 营销活动 | 13 |
| **港澳台/国际资费** | **1318** |

**只抓默认那一档，会漏掉 98% 的业务。**

**可选类型随分类变化，脚本会动态读取**：个人资费有上述四种，政企资费只有「加装包」一种。写死四种会导致政企整个分类被跳过 —— 这个坑踩过。

### 一个 UI 层面的限制

页面在**政企分类下，资费类型下拉里只有「加装包」一项**，没有套餐 / 营销活动 / 港澳台国际的入口。而接口层是支持的 —— 江苏政企本省实际还有套餐 35 条、营销活动 10 条，**页面点不出来**。

也就是说：**本版能抓到的，是页面 UI 能表达的全部**。想拿到 UI 没给入口的那部分，得用 [纯 API 版](https://github.com/cherry10086/cmcc-tariff-api)。

实测对照（江苏省，2026-09-12）：

| | 浏览器版 | API 版 |
|---|---|---|
| 页面能覆盖的 10 个组合 | 4591 条 | 4591 条（**逐项相等**） |
| 政企·本省·套餐 / 营销活动 | 抓不到 | 35 + 10 条 |
| **合计** | **4591** | **4636** |

## 工作原理

该页面是**加密网关后的 Vue SPA**：请求体与响应体都是 AES 密文，每次请求还带 `x-sign` / `x-nonce` / `x-token` 三重签名。硬逆向加密的话，站点一改版就废。

所以这里走**浏览器驱动**路线：用本机浏览器打开真实页面，让页面自己去加密、解密、渲染，脚本只从渲染后的 DOM 取数。代价是慢，换来的是站点改版后大概率还能跑。

## 数据完整性

抓取用的是无限滚动 + 下拉筛选，判断「加载完了没有」比想象中难。这里踩过的坑都在代码里堵死了，记录在此以便理解为什么代码长这样：

**坑一：只看卡片数会误判。** 请求已发出、响应还没回来时，卡片数同样不动。只看卡片数会把「正在加载」当成「已经到底」。现在同时盯**在途请求数**，请求在路上就继续等。

**坑二：某些省份不响应 `window.scrollTo`。** 实测江西用 `window.scrollTo` 滚到底，卡片数纹丝不动；键盘 `End` 和鼠标滚轮才让它继续加载。现在每轮同时用三种方式触发。

**坑三：滚动轮数上限设小了会截断。** 实测山东 661 条要滚到第 88 轮才加载完，按同比例换算，数据量大的省需要 200 轮以上。上限现为 400。

**代价有多大**：修复前江西只抓到 58 条、山东只抓到 39 条 —— **漏掉了九成**。

脚本会把这些如实标注出来，不替使用者下结论：

- 某个组合为空、且抓取期间源站**没有发起任何数据请求** → 标注「该地区未公示此类业务」。已人工核实上海、浙江的「政企资费 + 本省资费」确实为空，源站对空数据的处理方式就是不请求、不渲染（前端源码里连「暂无数据」这类文案都没有）。
- 如果某次抓取的新增数量异常高（超过 20 条且占比过半）→ 提示快照基线可能不完整，而不是让你以为天降几百个新业务。

### 自己验证：`audit.js`

抓取器自己说「加载完了」不算数。`audit.js` 用**完全独立的代码路径**重新抓一遍，用远超正常的滚动量（默认 160 轮，抓取器通常十几到几十轮就退出）把数据逼到底，再与抓取器的产出逐条对比：

```bash
node audit.js -p 山东省                  # 默认 160 轮
node audit.js -p 广东省 --rounds 300     # 数据量大的省多滚几轮
node audit.js -p 江苏省 --tab 政企资费    # 只审某个分类页签
```

它会打印完整的加载轨迹，告诉你数据在第几轮彻底饱和、与抓取器差多少条：

```
    轮次   卡片数   页面高度   在途
      0       10       8.4k      0
     19      145        98k      1
     39      370     248.5k      1
     59      479     322.3k      1
     88      661     445.5k      0   ← 饱和
    159      661     445.5k      0

独立抓取结果: 661 张
抓取器产出: 661 条（个人资费 · 山东资费）
差异: 0 条
✓ 一致 —— 抓取器没有遗漏
```

两者一致说明没漏；**审计结果更多就是抓取器漏了**，请带上输出提 issue。

> `audit.js` 只审计「个人资费 · 本省资费 · 套餐」这一个组合，是抽样检查。要核对全量，请用纯 API 版跑同一省份对数字。

## 快照机制

`snapshot-<省>.json` 是判定「新上线」的基线，**每次抓取后与旧快照合并写回**，不是覆盖。所以用 `--category` / `--scope` / `--type` 只抓一部分时，快照不会被裁剪。

基线一旦残缺，下次全量抓取会把旧业务整批报成「新上线」。为此设了三道闸：

| 闸门 | 作用 |
|---|---|
| 读取失败 ≠ 首次运行 | 快照存在但读取/解析失败时**跳过写入**并报警，绝不以本次范围重建基线 |
| 局部抓取不建残缺基线 | 用 `--category` / `--scope` / `--type` 抓取、且该省还没有历史快照时**跳过写入** |
| 新增占比异常告警 | 新增超过 20 条且占比过半时提示基线可能不完整 |

想彻底重来，删掉对应的快照文件，再跑一次**全量**抓取即可。

> 建议：某个省第一次抓取时跑**全量**，先把基线建全，之后日常巡检再用局部抓取提速。

## 站点结构（改版时看这里）

选择器集中在 `tariff-scrape.js` 顶部的 `SELECTORS` 常量里：

| 选择器 | 含义 |
|---|---|
| `.prov-entry` / `.select-item` | 省份切换入口 / 省份列表项 |
| `.tab-item` | 分类页签（个人资费 / 政企资费） |
| `.range-tab` | 归属页签（全网资费 / 本省资费） |
| `.line-3 .select-container .select-box` | **资费类型下拉的触发区** |
| `.line-3 .select-list-box .select-item` | **资费类型下拉的选项** |
| `.line-3 .select-container .tipsText` | 资费类型当前值（用于核对是否切换成功） |
| `.tariff-item-container` | 单个业务卡片根节点 |
| `.item-name` | 业务名称 |
| `.item-tips-list` | 字段明细块（资费标准 / 方案编号 / 上线日期 / …） |
| `.table-area` + `.row-title` / `.row-content` | 资源表，行由标题与内容交替构成 |

资费类型是个**自定义下拉**（不是原生 `select`），必须点开再选，且**切换后要核对当前值** —— 下拉有时会点空，不核对就会把上一轮的数据当成新类型的抓回去。

各类等待时长集中在 `WAIT` 常量里。若出现抓取条数明显偏少，先把 `WAIT.settle` 调大再试。

## 定时抓取

不建议挂常驻进程，用系统计划任务更省资源。

**Windows**：

```cmd
schtasks /create /tn "移动资费抓取" /tr "node C:\path\to\cmcc-tariff\tariff-scrape.js -p 北京市 --no-open" /sc daily /st 09:00
```

**Debian / Ubuntu**（`crontab -e`）：

```
0 9 * * * cd /opt/cmcc-tariff && /usr/bin/node tariff-scrape.js -p 北京市 --no-open >> /var/log/tariff.log 2>&1
```

每天跑一次，第二天的报告顶部就会列出这一天新上线的业务。

> 全量要 12 分钟，觉得慢可以退而求其次：日常巡检用 `--type 套餐 --type 加装包`，周末跑一次全量。

## 常见问题

**抓一次要多久？**
全量（16 个组合）约 12 分钟。用 `--type` / `--scope` 缩小范围会快很多，比如 `--scope 全网 --type 套餐` 只要一分多钟。

**为什么没有地级市？**
专区本身只按省维度组织，没有市级粒度。选江苏，看到的就是江苏省资费。

**某个组合显示「该地区未公示」，是对的吗？**
大概率是。这类组合源站**压根不发数据请求**。已人工核实上海、浙江确为如此。若与你手动打开网页所见不符，请告知。

**新增数量异常多？**
看告警。超阈值时脚本会提示快照基线可能不完整，别急着高兴。

**报「未找到 Chrome/Edge」？**
设环境变量 `CHROME_PATH` 指向浏览器可执行文件。

**Debian 下报缺少共享库？**
装浏览器时带上依赖：`sudo apt install -y chromium` 通常已处理；若手动装 Chrome，可能需要 `sudo apt install -y libnss3 libatk-bridge2.0-0 libdrm2 libxkbcommon0 libgbm1 libasound2`。
